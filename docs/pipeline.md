# Making a town

End to end, from a pair of coordinates to a deployed miniature. Every command
is `./town <verb>`; `./town <verb> --help` is authoritative for flags. The
stages and the files they write are summarised in
[ARCHITECTURE.md](ARCHITECTURE.md); the files themselves are described in
[data-format.md](data-format.md).

## 0. Set up once

```sh
git clone https://github.com/koomen/tinytown && cd tinytown
python3 -m venv .venv && .venv/bin/pip install -e .      # Python 3.10+; pillow, websocket-client; `town` on PATH
./town browser setup                                     # private headless Chromium into runs/headless-browser/
codex login                                              # for `town author` with OpenAI models
# or: .venv/bin/pip install -e ".[anthropic]" and export ANTHROPIC_API_KEY for Claude models
node --version                                           # 22+ for bake and tests
```

`./town` prefers `.venv/bin/python` automatically (`PIPELINE_PYTHON` overrides
it). `town serve`, `town build`, `town stage` and `town bake --check` need
nothing beyond the standard library.

## 1. Fetch the public data

```sh
./town fetch mytown --center 42.91201,-77.74548 --size 400,400 --title "My Town"
```

`--size` is metres east-west, north-south. Into `data/mytown/source/` go
OpenStreetMap (Overpass), a USGS 3DEP elevation grid and an Esri World Imagery
mosaic (the JPEG is gitignored). Everything is keyless; responses are cached
for 30 days in `data/.town-cache/`, so adjacent sites share tiles.
Re-running fetches only what is missing and refuses different coordinates
unless `--force`. `--no-satellite` is a quick terrain/roads/buildings preview;
repeat the command later without it to add the mosaic.

## 2. Build and look

```sh
./town build mytown
./town serve            # http://localhost:8734/?site=mytown
```

`town build` projects everything into local metres (x east, z south), clips
it to the box, guesses a style per building and writes `data/mytown/site.json`.
Trees, streets and generic buildings are generated by the viewer, so a town is
viewable before any building is authored. It takes milliseconds; re-run it
after every edit to `overrides.json`.

## 3. Decide what the miniature contains (optional)

Skip this for a small box: every footprint is in. For a campus, a village core
or anything with a boundary, freeze a scope:

```sh
./town scope mytown --bounds 42.908,-77.749,42.915,-77.742      # every mapped building inside
./town scope mytown --ids 247541316 248290075 --exclude 1090362840
./town scope mytown --ids-file ids.txt --title "My Town Centre"
```

This writes `sites/mytown/scope.json` (and a minimal `sites/mytown/site.json`
naming it if none exists). `town build` then includes only those ids and
`town stage` insists the scene matches. Re-running with the same arguments
changes nothing.

A site can also be carved out of another site's downloads without refetching:
`./town scope campus --source bigtown --bounds S,W,N,E` seeds
`data/campus/source/` from `data/bigtown/source/` and records the imported ids
in `source/composition.json`. When the site has a plugin with a
`scope_filter()` hook (Chautauqua: inside the Institution boundary), that hook
chooses the buildings when you give bounds but no ids.

## 4. References per building

```sh
./town plan mytown --limit 8 --out queue.txt     # what needs work, by prominence (landmarks, commercial fronts first)
./town refs mytown --list queue.txt               # head-on Street View of all four faces, 2 buildings at a time
./town refs mytown 247541316 --faces=+u,-v --dists 20,35
./town refs mytown --all --aerials                # crop aerials from the mosaic too (or `town fetch mytown --aerials`)
./town refs mytown 247541316 --web --extra-views 1   # assemble the model packet with a web photo and an oblique
./town brief mytown 247541316                     # buildings/247541316/brief.md + footprint.png
```

Captures drive google.com/maps in the private browser: stand `dist` metres out
from each face, let Maps snap to the nearest panorama, re-aim, hide the UI,
screenshot. Faces without coverage are recorded so they are not requested
again (`--missing` retries them deliberately). Keep `--workers` at 2; three or
more makes Google flaky. The images are reference material under the services'
terms: gitignored, never deployed.

`town author` runs this step itself for anything that is missing, so the
manual verbs are for when you want to inspect or steer.

## 5. Author, review, accept

```sh
./town author mytown --dry-run                  # status and next step per building; no model, no browser
./town author mytown --all --accept             # stages 3–6 for every unauthored structure (Codex CLI or ANTHROPIC_API_KEY, per model)
./town author mytown 247541316 248290075        # just these
./town author mytown --reauthor 247541316       # again, compared against the accepted blueprint
./town accept mytown --all-reviewed             # if you ran without --accept
./town status mytown
```

Defaults: `astra` authors (high effort), `sol` reviews (medium), 3 workers,
300,000 tokens per building and no run-wide cap, one self-check of the
author's own render, one validation fix per response, at most 2 repairs per
building, then forced publication of the best-scoring draft that `accept`
refuses without `--force`. The policy is in [authoring.md](authoring.md); the
hand loop (edit `draft.json`, `town lint`, `town render --compare`,
`town review --record`, `town accept`) is in [fixing.md](fixing.md). `accept`
writes `overrides.json` and rebuilds `site.json`.

## 6. Bake runtime assets

```sh
./town bake mytown              # surfaces-<hash>.bin.gz + surfaces.json, stream/manifest.json + chunks
./town bake mytown --check      # are they current? (no browser; this is what Cloudflare runs)
./town bake --viewer            # restamp index.html after editing src/
```

Surfaces are precomputed terrain and pavement rendered by the generator in
headless Chromium; streaming chunks are camera-sector geometry exported by
Node. Both are keyed by a fingerprint of `site.json` and of the generator
sources, so an unchanged input does no work. Commit the results: the deployed
site never generates them. Both exports are byte-reproducible: the same inputs
give the same files, and a re-export renames only the chunks whose contents
changed. The two run side by side when both are stale. Until a site is baked the viewer
falls back to in-browser generation and does not stream (`?stream=1` after
baking).

## 7. Add the site to a deploy target

Edit `sites/mytown/site.json` (created by `town scope`, or write it):

```json
{
  "title": "My Town, New York",
  "description": "A tiny interactive miniature of My Town.",
  "domain": "https://avon.town",
  "deploy": [{"target": "avon", "route": "/mytown"}],
  "plugin": "mytown",
  "scope": "scope.json",
  "landmarks": "landmarks.json",
  "outline": "outline.json",
  "social_image": {"alt": "…", "width": 1200, "height": 630}
}
```

`title`, `description` and at least one `deploy` placement are required to
deploy; the rest is optional. `route: "/"` makes the site the target's root;
`aliases` adds redirect-free extra routes. Optional per-site
`favicon.*`, `apple-touch-icon.png` and `social-preview.jpg` beside it replace
the repository-root ones. Add a `no-cache` line for the new route to
`_headers`. A new *target* (its own Worker and domain) needs an entry in
`sites/deploy.json` and a `wrangler.<target>.jsonc`; see
[deploy.md](deploy.md).

A plugin is optional: `tinytown/plugins/mytown.py` with any of
`extra_sources`, `landmarks`, `outline`, `refine_building`, `scope_filter`
([landmarks.md](landmarks.md)). Nothing in `tinytown/` may compare site names.

## 8. Stage, check, push, verify

```sh
./town stage --target avon              # dist/avon/, after bake --check and viewer checks
./town serve --dist avon                 # preview exactly what will be uploaded
tests/run.sh
git add data/mytown sites/mytown index.html _headers && git commit
git push                                  # Cloudflare Workers Builds runs `python3 -m tinytown stage --target avon`
./town verify avon https://avon.town mytown
```

## Growing an existing town

Keep the same centre and pass a larger `--size` with `--force` to
`town fetch`; existing ids keep their blueprints and notes, new ids arrive
generic and appear in `town plan`. `town build` records the footprint frame of
every accepted blueprint and lists drift in `frame_review.json`
(`review-frame` in the plan) so a moved footprint is reviewed before its
photos are overwritten. Then `town author --all --accept`, `town bake`.

## Moving old data

Sites laid out before September 2026 (`data/<site>/research/`,
`data/<site>/miniature/<id>/`, source files at the site root) move with
`./town migrate <site> [--dry-run]`, which uses `git mv` for tracked files and
rewrites absolute paths inside records to repository-relative ones.
